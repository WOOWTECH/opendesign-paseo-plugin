# OpenDesign Agent Connect 配對與升級

Agent Connect 是 OpenDesign 的連線設定入口，底層使用受管理的 Paseo daemon。它沿用原本的 `/paseo/setup/` 路徑與原生插件識別，不會因為名稱改變而建立另一份帳號或對話資料。

這份文件對應 `0.3.1`。實測結果以各次驗收紀錄為準；僅匯入 Skill 不會替任意 OpenDesign 主機安裝後端。

插件卡片版本與 Agent Connect 套件同為 `0.3.1`；設定頁的 Paseo 版本固定為 `0.17.5`，官方後續版本須先驗證相容再升級。三個公開 App 各自發布，App 顯示的版本可以不同，應連同當下測試結果一起記錄。

## 選擇測試端

| 設定頁目標 | App 網址 | 連線服務 |
| --- | --- | --- |
| Paseo（預設、行為基準） | https://app.paseo.sh | Paseo relay |
| Woowtech Smart | https://smart.woowtech.io | Woowtech relay |
| Apporo Smart | https://smart.apporo.ai | Apporo relay |

三個目標的 App、relay、主機品牌與配對資訊必須一致。主機品牌由本機選定目標在啟動時提供；切換目標需停止再啟動。受管理的 0.17.5 runtime 使用雜湊鎖定的相容修補加入主機確認所需的品牌欄位；官方檔案不符時拒絕套用。不要手動修改配對網址的網域，也不要將另一個目標的配對連結貼入目前的 App。

## 首次配對

1. 在 OpenDesign 的 Plugins → Expert suites → Personal 開啟 **Agent Connect**。
2. 檢查底層 Paseo 版本與服務狀態。首次啟動使用主機內建或鎖定的 runtime；已有帳號設定會沿用。
3. 選擇要使用的 App。若服務正在執行，切換目標只儲存選擇，必須按 **停止服務**、再按 **啟動服務** 才套用；停止中的服務不會因選擇 App 自動啟動。
4. 確認目前運行的目標與選擇一致，再建立配對連結。
5. 按配對按鈕前往選定的 App，完成該 App 顯示的連接確認。
6. 在 App 確認主機已連線、可讀取模型，再以同一個 agent 執行首輪與後續回覆。重新整理後仍能讀回這段對話，才算完成該項驗收。

設定頁產生連結不代表 App 已連上。頁面隱藏、連結到期或切換目標時，配對資訊會清除；需要時重新產生。不要將配對連結、OAuth 回呼或帳號金鑰貼到聊天與公開測試紀錄。

## 帳號與模型

Claude Code、Codex、Pi 使用各自的原生登入流程與主機供應商目錄。選擇 App 不會替供應商登入，也不會切換供應商帳號。

設定頁提供的模型清單以 daemon 當下回覆為準。CLI 已安裝、授權檔存在、模型清單可讀與真實模型回覆是不同的驗證項目。未登入、額度不足、請求逾時或權限等待都必須保留實際結果，不可當作兩輪對話通過。

## 升級與回復

升級候選會保留原來的 provider HOME、Paseo 身分、對話與工作區。舊 daemon 仍執行時需明確停止再啟動，才切換到新版 runtime。原先手動停止的服務不應在主機或設定頁重開後自行啟動。

升級前由操作者備份當前設定，並保留舊 runtime；套件不會自動建立升級前的設定快照。回復時先核對備份對應的版本，再還原設定及套件。0.17.5 一定會在 daemon 設定寫入 `daemon.relay.requireProtectedSecurity`（官方目標 true、品牌目標 false），舊版 0.11.2 讀到這個鍵會回 `CONFIG_INVALID`、Agent Connect 起不來：回到 0.11.2 時，先還原升級前的備份；沒有備份時，以應用使用者身分只刪這一個鍵（檔案維持 0600），約 40 秒後自動恢復，對話與身分都保留。若在 0.17.5 的 Devices 啟用了額外監聽位址，也先關閉。不要清空 Paseo HOME 或刪除 provider 目錄處理回復。

## 三端驗收紀錄

每次記錄 App 當下的版本與前端資源雜湊，因為公開網站可獨立更新。以官方 Paseo 的實際行為作為基準，分別記錄三端的配對、模型選擇、兩輪回覆、串流與停止、重新連線、歷史、檔案、終端、權限與適用的技能操作。

只在本輪建立的測試工作區執行寫入或清理。結果分為通過、失敗、受阻與不適用；保留失敗嘗試及清理結果。離線契約測試、安裝成功或初始頁載入，都不能取代配對與真實對話的實測證據。

## 同事實測操作

每個 App 使用自己的瀏覽器設定檔或無痕視窗。先在測試主機準備專用資料夾；三端均使用該測試範圍內的檔案與 agent。

1. 在 Agent Connect 選擇 App。若出現待套用提示，依序停止、啟動服務，確認運行目標一致再產生連結。
2. 在對應 App 按 **Paste pairing link**，貼上連結並按 **Pair**。核對主機確認畫面的資訊後按 **Connect**；若出現初始設定，完成或選擇 **Skip setup**。能看到正常側欄與 **New workspace**，才完成主機確認。單獨出現 Connected 文字不足以判定成功。
3. 按 **New workspace → Choose project → Add project → Existing**，選擇已授權的測試資料夾並按 **Open project**。若 App 顯示方式選擇頁，先按 **Search for directory**，輸入資料夾路徑後選取結果；部分 App 版本使用此流程。已列出的專案可直接選取。
4. 選 **Chat**，打開模型選擇器，先選供應商，再選模型。若選擇器直接顯示目前供應商的模型，先按返回再切換供應商。模式另由模式選單選擇。
5. 第一輪要求模型記住一個新的測試標記並回覆；第二輪不重複標記，要求模型讀回該標記。確認兩輪皆為 assistant 回覆，且仍是同一個 agent。重新整理與恢復網路後再核對歷史。
6. 串流測試需先看到實際輸出，再按停止，確認輸出停止增長。權限測試可在專用 agent 選 **Always ask**，分別拒絕與允許一項測試檔案操作，核對實際檔案結果。
7. 在工作區開啟 Files，測試新增、編輯、重新整理、重新命名、下載及刪除專用檔案。由檔案選單 **Add to chat** 測試工作區附件；由輸入框附件選單 **Upload file** 測試瀏覽器上傳，要求模型讀回檔案內的測試標記。
8. 工作區新增 **Terminal**，輸入短指令，核對指令下一行的實際輸出。重新整理後核對重播，再關閉終端並接受瀏覽器的關閉確認。
9. 在 **Settings → 該主機 → Agents → Orchestration skills → Choose skills** 檢查內建技能。記錄原設定，測試儲存單一技能選擇並核對安裝狀態，最後恢復原選擇與安裝開關；移除時需完成瀏覽器確認。

Pi 顯示的 **Default** 可以只是未設定模型時的佔位項目。若回覆為找不到 API key、需要 `/login` 等系統錯誤，應記錄未登入處理及模型驗收受阻，不能當成模型對話成功。未登入而建立的失敗 Pi 會話在主機重啟後可能沒有可讀的 session 檔；完成登入後應新建 agent 進行正向驗收。

驗收表至少記錄 App／套件／底層 Paseo 版本、供應商與模型、兩輪回覆、重新連線、串流停止、檔案附件、終端、權限、技能及清理結果。完成後只清理本輪建立的 agent、工作區與檔案，恢復測試前的設定。

## 版本紀錄

- `0.3.1`：只改建置。Alpine（musl）上的 node-pty 改用映像內同版本的 Node 標頭編譯（`npm_config_nodedir`），不再從 unofficial-builds.nodejs.org 下載；從亞洲連這台主機約 250 ms，正好碰上 Node 每個位址 250 ms 的連線嘗試逾時，Podman 全新安裝與叢集內建置會隨機以 `NATIVE_NODE_PTY_BUILD_FAILED` 失敗。失敗時把 npm 的錯誤尾段留在建置紀錄；CI 建置時封鎖下載主機。Paseo `0.17.5` 與 runtime 修訂號 `0.17.5-r2-186f173be43b` 不變，既有安裝不必重新安裝 runtime。回復說明更正為 `requireProtectedSecurity` 一定會寫入。
- `0.3.0`：改用官方 Paseo CLI `0.17.5`，提供 Paseo、Woowtech Smart、Apporo Smart 三個連線目標。
