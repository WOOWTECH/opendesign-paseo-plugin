# OpenDesign Agent Connect 配對與升級

Agent Connect 是 OpenDesign 的連線設定入口，底層使用受管理的 Paseo daemon。它沿用原本的 `/paseo/setup/` 路徑與原生插件識別，不會因為名稱改變而建立另一份帳號或對話資料。

這份文件對應 `0.3.0-rc.1` 候選分支。實測結果及交付版本以該候選的驗收紀錄為準；僅匯入 Skill 不會替任意 OpenDesign 主機安裝後端。

## 選擇測試端

| 設定頁目標 | App 網址 | 連線服務 |
| --- | --- | --- |
| Paseo（預設、行為基準） | https://app.paseo.sh | Paseo relay |
| Woowtech Smart | https://smart.woowtech.io | Woowtech relay |
| Apporo Smart | https://smart.apporo.ai | Apporo relay |

三個目標的 App、relay 與配對資訊必須一致。不要手動修改配對網址的網域，也不要將另一個目標的配對連結貼入目前的 App。

## 首次配對

1. 在 OpenDesign 的 Plugins → Expert suites → Personal 開啟 **Agent Connect**。
2. 檢查底層 Paseo 版本與服務狀態。首次啟動使用主機內建或鎖定的 runtime；已有帳號設定會沿用。
3. 選擇要使用的 App。若服務正在執行，切換目標只儲存選擇，必須按 **停止服務**、再按 **啟動服務** 才套用；停止中的服務不會因選擇 App 自動啟動。
4. 確認目前運行的目標與選擇一致，再建立配對連結。
5. 按配對按鈕前往選定的 App，完成該 App 顯示的連接確認。
6. 在 App 確認主機已連線、可讀取模型，再以同一個 agent 執行首輪與後續回覆。重新整理後仍能讀回這段對話，才算完成該項驗收。

設定頁產生連結不代表 App 已連上。頁面隱藏、連結到期或切換目標時，配對資訊會清除；需要時重新產生。不要將配對連結、OAuth 回呼或帳號金鑰貼到聊天與公開測試紀錄。

## 帳號與模型

Claude Code、Codex、Pi 使用各自的原生登入流程與主機供應商目錄。選擇 App 不會替供應商登入，也不會切換供應商帳號。

設定頁提供的模型清單以 daemon 當下回覆為準。CLI 已安裝、授權檔存在、模型清單可讀與真實模型回覆是不同的驗證項目。未登入、額度不足、請求逾時或權限等待都必須保留實際結果，不可當作兩輪對話通過。

## 升級與回復

升級候選會保留原來的 provider HOME、Paseo 身分、對話與工作區。舊 daemon 仍執行時需明確停止再啟動，才切換到新版 runtime。原先手動停止的服務不應在主機或設定頁重開後自行啟動。

回復前保留候選升級產生的設定備份及舊 runtime。若在 0.17.5 的 Devices 啟用了額外監聽位址，先關閉新增監聽並確認設定恢復為舊版可讀的格式，再回到不支援多監聽的版本。不要清空 Paseo HOME 或刪除 provider 目錄處理回復。

## 三端驗收紀錄

每次記錄 App 當下的版本與前端資源雜湊，因為公開網站可獨立更新。以官方 Paseo 的實際行為作為基準，分別記錄三端的配對、模型選擇、兩輪回覆、串流與停止、重新連線、歷史、檔案、終端、權限與適用的技能操作。

只在本輪建立的測試工作區執行寫入或清理。結果分為通過、失敗、受阻與不適用；保留失敗嘗試及清理結果。離線契約測試、安裝成功或初始頁載入，都不能取代配對與真實對話的實測證據。
