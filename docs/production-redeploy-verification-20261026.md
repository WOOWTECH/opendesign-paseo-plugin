# 正式環境完整 Redeploy 驗收（2026-10-26）

這是匿名驗收摘要。主機位址、服務識別碼、帳號、配對資料與部署證據保留在私有紀錄中。測試使用已授權的兩台相容主機，不能推論所有 OpenDesign 或 PaaS 安裝皆相容。

## 平台部署與版本保留

部署政策已經正式發布。實際 web／cron 工作負載的映像、資料庫模組版本、升級標記及健康檢查均通過；管理員可讀取固定版本欄位，既有一般租戶無法讀取這些欄位。

在兩台指定服務設定管理員專用的固定 chart／不可變映像，分別執行兩次真正的原生 `action_redeploy()`。每次都有 operator preflight、Helm revision 增加、服務回到 running 及初始化鎖釋放的證據；沒有 mock。

| 主機 | 完整 Redeploy | 保留內容 |
| --- | --- | --- |
| 標準主機 | 兩次通過 | chart 0.5.8、既有 Paseo 映像、1,832 個專案檔案、持久卷及初始化對話 |
| 含 Omnigent 的主機 | 兩次通過 | chart 0.5.8、較新的 Omnigent 0.1.6 映像、15 個專案檔案、持久卷及初始化對話 |

兩台主機的完整 Helm values 均未變更，共用商品範本與抽查的其他服務也未變更。這些 Redeploy 使用相同映像與工作負載設定，Pod 並未被強制重建；不能將本次結果解讀為冷啟動或節點故障演練。

## 外掛與模型對話

標準主機的 CLI Terminal、MCP Server、Paseo 入口在五種螢幕寬度的列表及詳細頁，實際點按開啟新分頁共 30 項通過。真實 stdio MCP 的狀態及三種模型目錄讀取成功，44 個 Paseo runtime 檔案與來源一致。

標準主機透過 Paseo 設定 GUI，使用該主機原有帳號，完成 Claude、Codex、Pi 各兩輪對話：

| Provider | 實測模型 | 第一則／後續回覆 |
| --- | --- | --- |
| Claude | `claude-haiku-4-5` | 通過／通過 |
| Codex | `gpt-6.1-sol` | 通過／通過 |
| Pi | `openrouter/cohere/north-mini-code:free` | 通過／通過 |

Claude 首次測試遇到另一程序正在更新 OAuth 的暫時錯誤；保留失敗證據，稍後單次重試才通過，沒有重設帳號或終止其他程序。這是暫時狀態恢復，並非本次新增程式修復。

含 Omnigent 的主機也使用自己的既有設定完成三種代理各兩輪對話：

| Provider | 實測模型 | 第一則／後續回覆 |
| --- | --- | --- |
| Claude | `claude-haiku-4-5` | 通過／通過 |
| Codex | `gpt-6.1-sol` | 通過／通過 |
| Pi | 工作區既有 LiteLLM 路由，`gpt-5.6-sol` | 通過／通過 |

此主機的 Pi 模型目錄只有兩條既有 LiteLLM 路由，不包含標準主機使用的 OpenRouter 模型。依當前目錄選擇一條可用路由後對話通過；原預設路由的對話失敗證據仍保留，不算已修復。沒有從其他工作區搬移帳號，也沒有重設供應商登入。真實 stdio MCP 狀態及三種模型目錄讀取成功，44 個 Paseo runtime 檔案及四個原生入口 manifest 均通過檢查。

含 Omnigent 主機的四個外掛入口也在 320、390、720、721、1440px 的列表與詳細頁完成 40 項實際點按、新分頁及目的地檢查。兩台合計 70 項通過。

## 官方 Paseo App

從標準主機的設定頁實際按下配對，官方 App 顯示該 daemon 為 Online／Relay，連線身分與產生的配對一致。在官方 App 選擇 Codex `gpt-6.1-sol` 與 Default permissions，建立測試對話並完成兩輪回覆；第二輪保留第一輪標記。

這項驗證與設定頁的對話測試分開執行。OpenDesign 的 Basic 帳密僅送到該主機來源；官方 App 使用獨立瀏覽器 context，配對資料保留在記憶體，不刊登在證據或 repo 中。本次官方 App 對話只實測 Codex；不將設定頁的 Claude／Pi 結果擴大解讀為官方 App 全模型驗收。
